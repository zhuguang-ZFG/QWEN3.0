# 全量审查与修复设计

## 1. 分阶段模型

本任务采用两个不可混合的阶段：

1. **审查冻结阶段**：记录根仓库与子模块提交、工作树、工具版本和门禁结果；建立覆盖矩阵；对发现逐条回溯真实调用链并冻结缺陷清单。
2. **修复验证阶段**：仅处理已复核发现，按严重度和依赖关系分批做 Ponytail 最小变更；每批增加直接回归证据并重跑相关门禁，最终执行全量门禁和逐项完成审计。

审查阶段不改产品代码。若门禁本身生成缓存或本地结果，只允许写入已忽略的工具目录或任务证据目录，不改变生产行为。

## 2. 审查边界与覆盖层级

### Tier A：生产关键路径

- 入口与 HTTP：`server_dlc.py`、`dlc_api/`、`routes/`。
- 核心绘图/写字：`dlc_core/`、`xiaozhi_drawing/`。
- 设备与状态：`device_gateway/`、`device_logic/`、`device_memory/`、`device_ledger/`、`device_policy/`、`device_workflow/`、`device_artifacts/`、`device_intelligence/`。
- 外部交互：`dlc_mcp/`、`device_voice/`、`integrations/`、`observability/`、根级鉴权/限流/ticket 模块。
- 配置与生产装配：`config/`、`common/`、`client_keys/`、依赖清单、Docker 和 nginx/部署装配。

### Tier B：独立交付面

- `esp32S_XYZ` 固件、设备协议、小程序及其服务端配套。
- `donglicao-site-v2/`、`donglicao-site/`、`chat-web/`、`docs-site/` 中仍有构建/部署入口的前端或站点。
- `sdk/`、`infra/`、`deploy/`、`.github/workflows/` 与活跃运维脚本。

### Tier C：支持与历史内容

- 测试、fixtures、migrations、模板与数据清单用于验证生产契约和测试有效性。
- `docs/archive/`、已退役代码说明、Agent/技能/Trellis 自身、缓存和生成输出仅做边界/残留引用检查，不作为生产实现逐文件审查对象。

## 3. 证据模型

每个发现必须记录：唯一 ID、严重度、状态、受影响契约、文件与行号、真实调用入口、触发条件、可观察影响、复现或静态证明、现有测试为何未覆盖、最小修复方向和验证命令。

发现状态仅允许：

- `confirmed`：代码路径和影响均有直接证据。
- `risk`：存在合理风险但缺少环境/真机/外部服务证据。
- `not-a-bug`：经调用链或设计文档证明为误报。
- `fixed`：修复与回归证据均完成。

Critical/High/Medium 在修复前必须二次复核，避免信任边界混淆、忽略设计注释和恒真测试等常见误判。

## 4. 数据流审查

至少完整追踪以下链路：

1. HTTP/MCP/小程序输入 → schema/鉴权 → `dlc_core` 路径生成与校验 → gateway 任务持久化 → WebSocket 下发 → 固件协议/运动执行。
2. 小程序登录/JWT → 家庭/设备所有权 → 任务、素材、图库、状态和审批操作。
3. 语音 ticket → WS 会话 → ASR provider → 任务意图/下发 → 超时、取消、断连和资源清理。
4. 部署清单 → VPS 文件集合 → 环境变量合并 → 启动/readiness → 回滚与生产域名验证。

每条链路同时检查生产者/消费者字段一致性、身份传播、错误语义、幂等/重试、并发状态、大小/时间限制和日志脱敏。

## 5. 修复策略

- 按“安全/数据丢失/运动风险 → 正确性/可用性 → 测试与维护性”的顺序修复。
- 每批尽量只触及一个契约边界；跨层字段变更必须一次同步生产者、消费者、类型/schema、测试和文档。
- 不做无证据的大重构；超过 300 行的新增/修改文件需拆分，现有遗留超限只在与确认缺陷直接相关时处理。
- 固件、小程序和运动栈修改前加载对应领域 skill。G-code/Grbl/运动下发变更后运行 fz `agent_gate --profile standard`；Host SIL 结果不替代真机结论。

## 6. 兼容、回滚与外部副作用

- 默认保持 HTTP/WS/MCP/设备协议向后兼容；必须破坏兼容时先写迁移和版本门控。
- 修复按独立批次保留可逆 diff；每批验证失败时撤销该批自己的修改，不触碰用户或其他任务改动。
- 本任务不部署、不烧录、不提交、不推送。网络型、生产型和硬件型验证只在已有授权/凭据且无外部写入时执行，否则记为环境限制。
